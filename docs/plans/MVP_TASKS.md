# MVP 开发任务清单

> 版本说明：本文件为早期规则闭环方案。结合系统设计文档后的最新实施主清单见 [项目 task-plan](../../task-plan.md)，后续任务编号及 Agent 能力验收以新清单为准。

目标：在现有 health_agent 项目中完成“查房提出检验随访计划 → 等待结果 → 结果匹配 → 医生审核确认 → 未完成任务进入交班”的可运行系统。

本文是实施清单，所有未勾选项均为待开发。保留现有 FastAPI、PostgreSQL 和医生端布局。第一版直接拆分并扩展现有 HTML/JavaScript，不把 React 迁移作为前置条件。

## MVP 范围

- 使用合成数据和开发医生身份。
- 支持一种意图：`FOLLOW_RESULT`，即等待指定检验结果。
- 支持一种缺口提醒：结果已返回，但在指定检索范围内未找到医生确认。
- 先用规则完成流程，最后接入可选真实模型。
- 一个 PostgreSQL 数据库、一个 FastAPI 服务、一个 Python Worker。
- 不需要 Redis、Docker、MCP、多 Agent 或云平台即可运行。

## 任务 01：修复当前前后端连接

依赖：无。

修改：`index.html`、`backend/main.py`、`backend/README.md`。新增：`frontend/api.js`。

- [ ] 抽出统一 API 请求方法、错误处理和病历字段转换。
- [ ] 点击“病历文书”时实际加载 API，不只在返回列表时加载。
- [ ] 后端返回空数组时显示“暂无病历”，不能保留演示病例。
- [ ] 明确设置演示模式和联机模式；联机请求失败时显示错误和重试入口。
- [ ] 保存失败不能提示保存成功，联机失败不能静默写入前端内存。
- [ ] 修复病历搜索字段、签署时间显示和病历正文安全渲染。

完成标准：联机模式下，从数据库读取并修改一份病历，刷新后仍能读取修改结果；空库和断网分别显示空态和错误。

- [ ] 将现有医生、患者和病历 ORM 模型拆出；保持原 API 路径兼容。
- [ ] 将数据库会话和配置集中管理。
- [ ] 配置 Alembic，为现有三张表建立初始迁移。
- [ ] 分别提供空库初始化与已有数据库的基线确认步骤；已有库必须先验证结构，不能直接无条件 stamp。

完成标准：在专用测试库升级成功；在现有库副本验证迁移后，原病历数据和接口仍正常。

新增：`backend/models/encounter.py`、`backend/routes/patients.py`、`backend/dependencies.py` 及迁移。

- [ ] 新增 `encounters`：患者、住院号、病区、入院时间、出院时间。

## 任务 04：定义任务状态与事件契约

依赖：03。

新增：`backend/domain/enums.py`、`backend/domain/state_machine.py`、`backend/schemas/workflow.py`、`tests/test_state_machine.py`。

- [ ] 定义意图：`FOLLOW_RESULT`。
- [ ] 定义事件：`ROUND_NOTE_CREATED`、`LAB_RESULT_CREATED`、`RESULT_ACKNOWLEDGED`。
- [ ] 定义任务状态：`PROPOSED`、`WAITING_RESULT`、`RESULT_AVAILABLE`、`ACKNOWLEDGED`、`RESOLVED`、`REJECTED`、`CANCELLED`。
- [ ] 定义事件、候选意图、证据、提醒与审核输入输出结构。
- [ ] 实现合法转换校验；模型不能任意设置状态。
- [ ] 明确“接受提醒”“已查看报告”“已闭环”为三个不同操作。
- [ ] 拒绝未知字段、无时区时间和缺失患者/住院标识。

完成标准：无证据不能进入报告可用状态；无医生确认不能进入已查看或已闭环；非法状态跳转被拒绝。

## 任务 05：保存查房与临床事件

依赖：04。

新增：`backend/models/rounding.py`、`backend/models/event.py`、`backend/routes/rounding.py`、`backend/routes/events.py` 及迁移。

- [ ] 新增 `rounding_sessions`、`clinical_events` 和 `event_jobs`。
- [ ] `POST /api/rounding-sessions` 保存查房原文、医生、患者和住院信息。
- [ ] 保存查房与创建事件、待处理队列记录使用同一事务。
- [ ] 增加开发模式的模拟检验事件录入接口。
- [ ] 事件保存来源编号、发生时间、接收时间、检验项目及标本/医嘱标识。
- [ ] 使用幂等键避免重复请求产生重复事件。

完成标准：页面录入查房后刷新仍可查看；重复提交同一幂等键不会生成第二个事件；事务失败不留下半条流程。

## 任务 06：提取并确认随访任务

依赖：05。

新增：`backend/models/task.py`、`backend/services/intent_extractor.py`、`backend/routes/tasks.py` 及迁移。

- [ ] 新增 `clinical_tasks`，记录目标检验、来源事件、负责人、状态、到期时间、父任务和版本号。
- [ ] 用规则识别“血培养结果出来后通知我”等表达，生成候选任务。
- [ ] 保留原始引用片段，未明确的目标或日期标记待确认。
- [ ] 排除“无需复查”“此前已经查看”等明显非新随访意图。
- [ ] 医生可修改目标、确认或驳回候选任务；确认后进入等待结果。
- [ ] 提供任务列表、详情、确认和驳回 API。

完成标准：查房原文能形成一条带来源的候选任务；只有医生确认后才开始跟进；重复处理不重复创建任务。

## 任务 07：建立可恢复的后台 Worker

依赖：06。

新增：`backend/worker/main.py`、`backend/worker/processor.py`、`backend/models/agent_run.py`。

- [ ] Worker 从 PostgreSQL `event_jobs` 领取待处理事件。
- [ ] 将候选提取和后续报告处理放入 Worker；API 只提交事件。
- [ ] 保存处理状态、重试次数、重试时间、失败原因与运行记录。
- [ ] 设置有限重试；中断任务有租约/超时恢复机制。
- [ ] 为事件处理结果建立唯一约束，重试不能重复创建任务或提醒。
- [ ] 等待条件保存进数据库；每次继续处理时重新读取当前上下文。

完成标准：停止再启动 Worker，未处理任务会继续执行；处理过程中中断后可恢复；失败与等待在页面上能区分。

## 任务 08：匹配报告并生成证据提醒

依赖：07。

新增：`backend/services/result_matcher.py`、`backend/models/evidence.py`、`backend/models/finding.py`、`backend/services/verifier.py`。

- [ ] 按患者、住院、检验项目、标本/医嘱及时间匹配结果。
- [ ] 保存来源报告 ID、版本、原始结果和引用关系。
- [ ] 未唯一匹配时标记待核实，不自动选择报告。
- [ ] 在配置的提醒条件满足后，生成“已搜索来源中未找到确认记录”的待审核提醒。
- [ ] 提醒保存支持证据、检索来源、检索截止时间和 run_id。
- [ ] 报告先到、任务后建时重新检索已有结果。
- [ ] 新报告版本不得直接沿用旧报告确认状态。

完成标准：正确报告能产生提醒；错患者、错住院不关联；重复事件不重复提醒；查询失败不能解释为未确认。

## 任务 09：实现医生审核、结果确认与审计

依赖：08。

新增：`backend/models/review.py`、`backend/models/audit.py`、`backend/services/review_service.py`、`backend/routes/reviews.py`。

- [ ] 医生可接受或驳回提醒；驳回填写理由，保留原提醒。
- [ ] 增加针对指定报告版本的“已查看结果”操作。
- [ ] 增加带处理说明的“关闭任务”和带理由的“取消任务”。
- [ ] 支持医生明确选择“继续等待药敏”并建立关联后续任务。
- [ ] 服务端执行权限、状态、证据和版本校验。
- [ ] 审核、确认和状态变化追加审计记录；业务 API 不提供审计修改/删除。
- [ ] 重复点击不产生重复审核；旧版本操作返回冲突提示。

完成标准：接受提醒不自动关闭任务；已查看不自动等于已处理；每次操作都有医生、时间、理由和状态变化记录。

## 任务 11：生成真实任务驱动的交班草稿

依赖：10。

新增：`backend/models/handoff.py`、`backend/services/handoff_service.py`、`backend/routes/handoffs.py`。修改：交班界面。

- [ ] 用数据库任务和证据生成交班，替换固定示例文字。
- [ ] 分别展示已确认事实、待审核事项、未完成任务及关注事项。
- [ ] 草稿保留 task_ids、evidence_ids、生成时间和数据版本。
- [ ] 点击事项能回到对应任务/报告。
- [ ] 医生确认的交班快照只读；新事件到达后提示有更新，可生成新版本。
- [ ] 交班确认不能自动关闭任务。

完成标准：尚未返回的药敏任务出现在交班中；已关闭任务不作为未完成事项；后续事件不篡改历史交班。

依赖：05、09。

修改：病历模型、路由、查房草稿 UI。

- [ ] 新增创建病历草稿 API，替换当前“保存草稿”的提示行为。

- [ ] 签署病历不改变随访任务或报告确认状态。

完成标准：同一次查房可查看对应病历和随访任务；病历真实保存；病历与任务审核状态相互独立。

新增：`backend/providers/base.py`、`backend/providers/rules.py`、`backend/providers/llm.py`。修改：`.env.example`。

- [ ] 通过 `AGENT_PROVIDER=rules|llm` 选择来源，规则方式无需密钥。

完成标准：相同后端与 UI 可切换规则和模型；缺密钥或超时不影响已保存数据；规则成绩与模型成绩分开记录。

## 推荐执行顺序

```text
01 连接修复
 → 02 迁移与拆分
 → 03 住院与权限
 → 04 状态契约
 → 05 查房事件
 → 06 候选任务
 → 07 Worker
 → 08 报告与证据
 → 09 审核闭环
 → 10 医生端
 → 11 交班
 → 12 病历衔接
 → 14 规则版验收
 → 13 可选真实模型
 → 14 补充模型评测
```

测试随相关任务一起实施，任务 14 负责汇总与全链路验收。先交付规则驱动的闭环 MVP，再接入真实模型。第一项实际开发任务为任务 01。
